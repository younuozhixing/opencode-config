# Quick reference — the whole guide on one page

Every rule and bug-shape as one scannable line, deep-linked to the
full text. This is the **index**, not the rules — when a line
matches your task, open the link before you code. (The depth, the
examples, and the war stories live in the linked sections; this page
deliberately does not repeat them.)

Start at [`CLAUDE.md`](CLAUDE.md) for the loop + trigger index;
[`engineering-rules.md`](engineering-rules.md) for the depth;
[`review-checklist.md`](review-checklist.md) before "done";

like* a known bug.

## The loop (every task)

1. **Understand** — don't assume; reproduce/diagnose before you change; ask when unclear.
2. **Plan** — weigh 2–3 approaches before committing (record why, §18.3); make the goal verifiable (test-first); run the trigger index.
3. **Implement** — minimum code, surgical edits, clean only your own mess; Rust by default, reusable code → `unolib`.
4. **Verify** — run the checklist; state what you ran and what it told you.

## Engineering rules — one line each

| § | Rule | The line |
|---|---|---|
| 1 | [Naming](engineering-rules.md#naming) | User-visible strings live in the uno-namespace (positive rule); external addresses are exempt; a ground-up rewrite is a clean break, not a fork — new namespace/structure all the way through, interop with the legacy only at one narrow seam (schema as data, not code), drift back into legacy names/layout is a regression (§1 clean rewrite). |
| 2 | [Units](engineering-rules.md#units) | SI, never implicit. Correlated timestamps: one clock/epoch/unit (§2.1); intrinsics are pixels at ONE resolution (§2.2); a fork's inherited hardware constants are the upstream's — re-derive (§2.3). |
| 3 | [Safety-critical](engineering-rules.md#safety-critical) | Actuator authority with no backstop → name path + failure mode, ask before merge; secondary surfaces view-only (§3.1), e-stop always on (§3.2), watchdogs documented (§3.3); takeover feeds latest-wins, never live-re-cap resolution (§3.4); safety inputs gated on correlated symptoms, fail safe loudly — and running-on-defaults is a STATE: persistent operator indicator until a valid input is accepted — verify applied on target (§3.5); a periodically-recomputed decision (plan/route/selection/mode) re-validates + holds the current one with hysteresis — don't recompute from scratch each tick or it flaps (§3.6); an adaptive-quality loop budgets the TOTAL shared link and divides it among consumers, never one independent per-stream loop (§3.4); a command link that actuates safe-stops on staleness — check command freshness (unmaskable) each tick, bail to a validated safe state, never replay the last command after the link drops (§3.7); a feedback loop closes on the variable it controls, not a proxy that decouples (motor rpm vs ground speed under slip) and makes it hunt — sense the real variable or cross-check + fail safe (§3.8). |
| 4 | [Schemas](engineering-rules.md#schemas) | Append-only; never renumber/reorder — the wire keys on ordinal, not name. |
| 5 | [Messaging hot path](engineering-rules.md#messaging-hot-path) | SHM first; bulk travels by reference (§5.1); drain all items per wake (§5.2); one publisher per topic — a base default that publishes is a publisher, and **opening** a publisher on a claim-on-create transport claims the topic even if you never send (never open one on a topic you only consume; a keepalive publisher assassinates the real producer) (§5.3); a bridge/forwarder derives its served set from the live components by type, never a hand-maintained name-list that silently drifts and drops a new one (§5.4). |
| 6 | [Process supervision](engineering-rules.md#process-supervision) | Gate predicate, never "always run"; one declarative process table (§6.1); `Restart=always` for boot races, escalate power-cycle faults — but `Restart=always` is defeated by the start-limit (a fast-flapping unit wedges in `failed` permanently), so a must-always-run service sets `StartLimitIntervalSec=0` in `[Unit]` + a generous `TimeoutStopSec`, and "stale data" is diagnosed with `systemctl is-active` first (§6.2); clients never `stop` an always-on service (§6.3); reconnect bounded + frees the old handle (§6.4); never login-bound — logind reaps user IPC (§6.5); isolate eager plugin imports (§6.6); an always-on job is a resident loop under start-on-load + restart-on-exit, not a cron/calendar one-shot — a one-shot has no process between fires, can't boot-start or self-heal, and reads as idle/dead (§6.7); a process that must run once guards single-instance (lock/claim, take-over-and-reap) + reaps the predecessor — a silent duplicate writes the same shared state and the system goes stale/flaps; the singleton is the **role not the binary** — a different *implementation* (a rewrite beside the legacy) is also a duplicate; onboard one by **disabling (not just stopping) + reaping** every other across scopes, for the whole registry-derived set, at the privileged cutover AND the per-activation claim — disjoint resources may coexist, shared ones collide; on restart retry the claim over a bounded window (a reaped predecessor's port/lock release lags the restart — a one-shot claim hits EADDRINUSE and falsely reports "already running") (§6.8); stop a worker COOPERATIVELY before killing it — signal a stop flag + wait bounded for it to exit (releasing its codec/handle/lock), escalate to SIGTERM/SIGKILL only on a hang; an immediate kill mid-operation segfaults (§6.9); a daemon's access to its devices (serial/USB/CAN/GPIO/GPU) is provisioned in the UNIT (group/capability/udev ACL), not your interactive shell — a missing group → PermissionError at open → "sensor invalid"; surface the open-failure loudly (§6.10). |
| 7 | [Silent-default traps](engineering-rules.md#silent-defaults) | Distinguish absent from false at the boundary: falsy KV defaults (§7.1), `getattr` on a moved field (§7.2), wrong-value arg defaults (§7.3), companion bool for overrides (§7.4); **no env-var switches — the most-violated rule** (§7.5); pushed overrides expire by freshness (§7.6). |
| 8 | [UI architecture](ui-rules.md#ui-architecture) | Snapshot pattern is house style; colours from the theme, and a status indicator's off/false state is per-site semantic — `off=IDLE|WARN|BAD`, a fixed off-colour paints a real fault benign (§8.25); house visual language §8.28; operator actions idempotent + re-runnable §8.29; telemetry/debug viz logs to Rerun §8.30. Sub-rules below. |
| 9 | [Rust vs Python](engineering-rules.md#rust-vs-python) | **Org default: Rust** — Python only for Qt/imgui UI, ML glue, true one-offs; mandatory on a measured hot path (§9.1) or silent-corruption path (§9.2); FFI validates at the unsafe edge (§9.3); accelerators: explicit device + log which bound (§9.5–9.8); load-bearing caps stay (§9.9); validated GPU path is the default (§9.10). |
| 10 | [Per-stream isolation](engineering-rules.md#per-stream-isolation) | One stalled stream must not freeze the rest; shared probes must not false-flag encode-only sources; capped per-element auto-recovery. |
| 11 | [Cross-compile](delivery-rules.md#cross-compile) | `cargo-zigbuild`; link the lib built for the target platform+arch (§11.1); a freezer silently drops modules whose native dep is missing — verify by importing (§11.2); drive builds off a declared target matrix (one toolchain-activation command per target, pinned inputs, whole matrix), and cross-build for the real target early — the host build is not representative, target-only code (cfg/ABI/libc) breaks only on the target's triple (§11.3); a binary finds its shared libs via a baked relocatable rpath (`$ORIGIN`/`@loader_path`), never an `LD_LIBRARY_PATH`/`DYLD_*` env crutch or a post-hoc patchelf (§11.4). |
| 12 | [Embedded sync](delivery-rules.md#embedded-sync) | rsync excludes native-arch binaries; stamp builds `git_sha`+dirty (dirty via `git status --porcelain` — staged + untracked, not `git diff`) and diff stamps before debugging (§12.1); compat = required ⊆ advertised features, never a peer version string (§12.2); version-gate the deploy to skip redundant rebuilds, gating on `sha+dirty` so an uncommitted edit can't take the committed sha and silently not-ship (§12.3). |
| 13 | [Source vs deployed](delivery-rules.md#source-vs-deployed) | Gitignore generated output; don't assume the dev layout at runtime (§13.1); depend on the published prefix, never a sibling source tree (§13.2); a hot-edit on a deployed box is a loan — capture it back same-day, diff the target before deploying (§13.3); an artifact hand-installed into a build-regenerated dir (venv site-packages, `target/`) is wiped by the next build — install deps via the build's manifest, ship code+dep as one paired unit, verify by loading (§13.4); share must-be-present content (rules/config/schemas) as vendored COPIES + a path-limited copy-in step, not a submodule — a submodule breaks builds on a missing `--recurse-submodules` (empty dirs) or a `file://` URL (blocked by git 2.38+, CVE-2022-39253); reserve submodules for versioned code (§13.5). |
| 14 | [Bundled config](delivery-rules.md#bundled-config) | Bake is explicit + gitignored; runtime seeds from it but doesn't trust it; prefer a **secret-free** bundle — ship non-secret defaults, seed the credential per-device at runtime, gate the ship on a no-secret grep (a distributable artifact leaks any baked token to every recipient) (§14.5). |
| 15 | [Diagnostics](delivery-rules.md#diagnostics) | Diagnostic-first — the command that proves the cause before the edit (§15.1); extend probes (§15.2–15.4); link up ≠ data flowing (§15.5); a "floor" names its mechanism (§15.6); capture state before any reboot (§15.7); diff the working reference, one hypothesis, 3 failed fixes = stop (§15.8); rate meters count in a window, never smoothed 1/Δt (§15.9); read liveness from the data link, not a side-channel probe (§15.10). |
| 16 | [Logging discipline](delivery-rules.md#logging) | Transition + heartbeat, never per-tick; rate-limit per source; a perpetually-red signal is no signal (§16.6); a slow log sink can starve a core / reboot the SoC (§16.7); format each line once — one owner of the prefix, the framework's target ≠ a hand-written `[tag]` (§16.8); record message streams ONE way — the shared `unomsg::ulog` log of record, Rerun views it but never persists a `.rrd` (§16.9); a record-stream reader recovers from a torn trailing record (mid-record EOF = clean stop, not a whole-log error) (§16.10). |
| 17 | [Validation surfaces](delivery-rules.md#validation-surfaces) | The canonical entry point IS the validation surface; side-channels are debug tools. |
| 18 | [Tests / verification](delivery-rules.md#tests) | State what you ran and what it told you; representative smoke probes (§18.1); migration done = surface diff (§18.2); settle decisions with recorded evidence (§18.3); wrappers propagate the real exit code (§18.4); test-first RED→GREEN→REFACTOR (§18.5); **every bug fix ships a PERMANENT guard that reds on reintroduction — no guard = unenforced fix; when a later change reds an old guard, reconcile BOTH requirements, never delete/xfail it; mark deliberate-looking-wrong code (re-export, magic const, list ORDER) with `# noqa`/`// keep:` + reason so a refactor/auto-fixer can't revert the fix — a bug that keeps coming back is unguarded, not hard (§18.5.1)**; mocks at the boundary, never the assertion target (§18.6); an automating tool is done at the consumer-visible committed/pushed/registered state, not files-written — finish the handoff, path-limited commit (no `add -A`), idempotent with the skip-check keyed on the published state — `local == remote`, not a local marker, else a committed-but-unpushed tail is stranded across re-runs (§18.7); a rewrite of a transform proves behavioural parity by dual-running legacy + new on the same real recorded data (bit-identical or stated tolerance), gating cutover on it (§18.8); validate a recovery/fallback path by INJECTING the fault (kill the link, kidnap the estimate, truncate the file) — it never runs in normal operation so it and its detector rot, assert detect + recover, keep the injection (§18.9). |
| 19 | [Reversibility](delivery-rules.md#reversibility) | No destructive op without explicit OK; secrets untouched; atomic writes (tmp+rename); deletes by allowlist, never glob (§19.1); hard-cap eviction deterministic, not signal-gated (§19.2). |
| 20 | [Repo hygiene](delivery-rules.md#repo-hygiene) | Right remote, right branch; merge only YOUR committed+validated work, FF off-checkout, never `add -A` (§20.1); concurrent/risky work gets its own git worktree (§20.2); **"commit" = the full finish sequence** (commit→FF-to-default→push→delete your merged branch→checkout back), not a bare `git commit`; finish the branch — merge / park-with-recorded-blocker / delete, checkout back to default; unmerged set enumerable by one command (§20.3). |
| 21 | [Python env](delivery-rules.md#python-env) | `uv` is the default: `uv add` + commit `uv.lock`, never bare `pip install`. |
| 22 | [New service checklist](delivery-rules.md#new-service-checklist) | Name + consumer + gate + rationale — all four, or it's not ready. |
| 23 | [Network topology](delivery-rules.md#network-topology) | Cloud edge is plumbing; authless only if the edge provably can't route in (§23.1); reverse-proxy subpath = relative URLs (§23.2); edges throttle NEW connections — keep-alive + backoff, bake the SSH mux into `~/.ssh/config` (rig alias + the bastion Host BOTH ControlMaster) and reach via `ssh <alias>`/a helper, never an ad-hoc per-command `ProxyCommand` (2 un-muxed edge conns/cmd → MaxStartups saturation) — in Unomove that helper IS `uno-rig`/`unojump` (`unogui.app.unorig`); route ALL rig ssh/scp/rsync + control/command paths through it, never raw `ssh` (bare `ssh <alias>` is fine — it's the muxed path; if `uno-rig` false-reports "tunnel down" while the alias works, trust the alias + check the registry §23.4); and behind a flaky HTTPS proxy default git push to key-based SSH-443 via `pushInsteadOf` (§23.3); reach a fleet host via its registry's `lan_ip`+`last_seen`, never a hardcoded IP or scan (§23.4); a transport drop mid-write ≠ a failed write — re-verify the end-state with an idempotent read before retrying, make the write idempotent (§23.5). |
| 24 | [When in doubt](delivery-rules.md#when-in-doubt) | Crosses repos you can't see / unwritten constraint / two non-obvious paths → ask. |
| 25 | [External integration](delivery-rules.md#external-integration) | A reconcile poll is the correctness floor — push is latency only (§25.1); writes idempotent, upsert by stable id (§25.2); structured source over OCR/LLM, validate the lossy fallback (§25.3). |
| 26 | [Money / privileged actions](delivery-rules.md#trust-boundary) | The server is the trust boundary: recompute money/authz server-side (§26.1); dual control + audit for irreversible actions (§26.2); demos isolated from prod by construction (§26.3); grant access by the requester's OWN public key on a least-privilege account behind an approval gate, never a shared password/private key — can't revoke one person, loses attribution, one leak rotates everyone (§26.4); at fleet scale a key-per-host is O(identities × hosts) — trust a central SSH user CA issuing short-lived per-identity certs (enroll once → reach all, KRL revokes fleet-wide) (§26.5); untrusted data crossing into an interpreter (HTML/JS, SQL, shell, template) is encoded for that sink — auto-escape on output (right context), parameterize on input (bound params / argv array, never `shell=True`/string-built SQL) — never interpolated raw, else it becomes code (XSS, SQL/command injection); encode at the sink, treat stored values as untrusted when rendered (§26.6). |
| 27 | [Fixing a build](delivery-rules.md#build-fix) | Method, not flag-poking: clean committed tree → pin inputs → localise the layer → build for the target → verify on the deployed form → record. |
| 28 | [Reuse the critical path](engineering-rules.md#reuse-critical-path) | ONE shared validated module every caller imports — cross-project that home is `unolib` (Rust-first); a shared fix is done at ROLLOUT: publish, fleet-bump every pin, confirm by stamp; every `unolib` publish ships linux x86_64 AND aarch64 (§28.1); a cross-language lib publishes a stable narrow ABI + thin client, consumers own the schema, the ABI is the compat contract (additive=no reship, format/header bump=reship+re-pin), ship the published client not the internal workspace, config not CWD-relative (§28.2); a built lib self-reports a queryable version — verify the one LOADED not the source, rebuild every triple from one version atomically (partial rebuilds mix versions across a shared prefix) (§28.3); a shared lib that defines boundary-crossing types resolves to ONE version in the graph — pin once, align every consumer; two versions = same-named types don't unify (`expected Service, found Service`) + C-ABI UB (§28.4); a published version tag is IMMUTABLE — never move it (resolvers cache tag→sha, a moved tag breaks/no-ops), burn a mis-cut/poisoned number and cut a fresh higher one, verify the tag from a clean fetch before consumers depend on it (§28.5). |
| 29 | [Control flow](engineering-rules.md#control-flow-dispatch) | **Try not to use `if/else` — if you must, that's the signal to redesign, not to add the branch.** A conditional that decides *business behaviour* wants to be data (a `{kind: handler}` dispatch table), a type (polymorphism / strategy), or an explicit state machine (§3.6). The only `if` that stays: a **guard clause** (early-return on bad input) or a **defensive boundary fallback** (I/O / parse / external API that must never raise, §7/§25) — and those live in ONE centralised helper, never copied across callers (that's §28 duplication in conditional form). |

### §8 UI sub-rules

| § | The line |
|---|---|
| [8.1](ui-rules.md#layer-boundary) | No widget/window imports below the service layer boundary. |
| [8.2](ui-rules.md#snapshot-pattern) | Service = immutable snapshot; build-complete-then-swap; `live: bool` field. |
| [8.3](ui-rules.md#lifecycle-hook) | One `stop` hook per worker, run LIFO at exit; signals route through the same shutdown. |
| [8.4](ui-rules.md#view-error-containment) | `@safe_view`: a per-frame exception degrades to a banner, not a dead app. |
| [8.6](ui-rules.md#coalesced-publishes) | Streaming output coalesces (≤N events OR ≤T ms), never per-line snapshot copies. |
| [8.8](ui-rules.md#texture-lifecycle) | GPU texture upload gated on a dirty/seq flag, not every frame. |
| [8.9](ui-rules.md#input-arbitration) | Driving-input consumers check `want_capture_keyboard` first (safety). |
| [8.11](ui-rules.md#orphan-sweep) | Orphan-sweep child processes at startup, conservative match. |
| [8.14](ui-rules.md#fonts) | One Unicode-wide font; every glyph via a `SYM` constant verified present. |
| [8.15](ui-rules.md#i18n) | English is the msgid; `tr()` every string; no concatenated fragments; layout absorbs expansion; static font instance. |
| [8.16](ui-rules.md#animation) | Animation is dt-correct (`1-exp(-dt/τ)`), not a fixed per-frame step. |
| [8.18](ui-rules.md#banner-pattern) | Status banner: muted first frame, green/amber/red, hover detail, rate-limited probe. |
| [8.19](ui-rules.md#wire-state-mirror) | Control widget renders the value **on the wire**, not local input (safety). |
| [8.20](ui-rules.md#overlay-staleness) | Overlays distinguish "alive but silent" from "broken" (explicit no-data state). |
| [8.21](ui-rules.md#fault-localization) | Multi-hop workloads expose per-hop status — fault localised in 5 s. |
| [8.22](ui-rules.md#masking) | Mask infra detail + sensitive data by default; reveal on explicit action; gate server-side too. |
| [8.23](ui-rules.md#device-sizing) | Size for the device; fix layout overlap in code, bump the cache key, verify cold. |
| [8.24](ui-rules.md#framework-chrome) | Owning a surface = disable the framework's default chrome, not draw over it. |
| [8.27](ui-rules.md#verify-after-write) | A control action confirms by **read-back**, never the write's return code (safety); "issued" ≠ "applied". |
| [8.28](ui-rules.md#house-design-language) | House style = Song-minimalist: ink on rice-paper, hairline structure, one cinnabar accent, 留白; tokens from one theme module. |
| [8.29](ui-rules.md#rerunnable-action) | An operator action that drives a flow (onboard/link/enroll/deploy) is idempotent + re-runnable — a re-press converges (skips done, retries failed); re-run is the one-click recovery, never a one-shot that strands a half-done state needing a CLI. |
| [8.30](ui-rules.md#rerun-visualization) | Multimodal / time-series telemetry & debug viz logs to **Rerun** (`rerun-io/rerun`) — render/scrub/replay every modality on one timeline; don't hand-roll a viewer. A live/replay **VIEW, never a record**: `connect_grpc` live or replay the unomsg `.log` (§16.9), never `rr.save(".rrd")`. Introspection layer, not the control surface. |

## Review checklist — the gate before "done"

Run [`review-checklist.md`](review-checklist.md) over the diff. Groups:

- **A** Scope — every line traces to the request; reuse before reimplement; Rust/`unolib` defaults; hot-edits captured back; shared fixes rolled out.
- **B** Naming — uno-namespace; no vocabulary collisions.
- **C** Units & schemas — SI; append-only; clocks/resolutions pinned; drain per wake; sole publisher.
- **D** Safety-critical — actuator path named; view-only secondary; e-stop always on; feeds latest-wins.
- **E** Process supervision — gate predicate; restart policy; bounded reconnect; not login-bound.
- **E.bis** Silent-default traps — no falsy-default / `getattr` / env-var / stale-override trap.
- **F** UI — wire-state mirror; verify-after-write; re-runnable operator action (one-click recovery); telemetry/debug viz → Rerun; banner triad; overlay staleness; device sizing.
- **F.bis** Logging — transition+heartbeat; rate-limited; no per-tick in async.
- **G** Embedded sync/deploy — native-arch excluded; build stamp + diff-before-debug.
- **G.bis–quint** Rust/FFI · accelerators · Python env (`uv`) · external services.
- **H** Tests — diagnostic-first; test-first; truthful exit codes; honest rate meters; said what you ran.
- **I** Reversibility & secrets — no destructive op unasked; allowlist deletes; right remote/branch.

## Anti-patterns — recognise the shape (see [`anti-patterns.md`](anti-patterns.md))

> Most of these are re-runs of **six recurring cycles** — silent
> authoritative-vs-actual divergence · "looks healthy" ≠ working ·
> silent-falsy default · wrong-platform artifact · always-asserting
> carries no information · decision oscillation. Recognise the cycle,
> fix the class. See [Recurring shapes](anti-patterns.md#recurring-shapes).

1. UI panel dead/stuck — the bridge isn't forwarding its topic; check the bridge set first.
2. "Default ON" off on fresh install — KV store returns falsy, not None.
3. `widget.close()` from a worker thread — macOS deadlock; queue it.
4. Host-arch binary clobbered target binary on sync — exclude it from rsync.
5. Blocking the async event loop (CPU or a slow sync call) — offload; never probe inline.
6. Conflating four similar identifiers — one name per form.
7. Side-channel works, canonical path doesn't — fix the canonical path.
8. Assumed default branch name — read it, don't assume `main`.
9. Wire-format compatibility creep — absence of interop is deliberate.
10. Cloud edge vs reverse tunnel — edge is plumbing.
11. Naming-drifted cancellation protocols — one primitive per project.
12. Per-event publish under load — coalesce.
13. Unbalanced framework stack on exception — unwind to the view's start depth.
14. Input listener eats keys while a text field has focus — safety footgun.
15. Per-tick allocator in a tight loop — pre-build and reuse.
16. Schema misread via `getattr(…, default)` — moved field reads falsy forever.
17. Daemon "runs" but publishes nothing — silent permission/resource failure.
18. Threshold-pair drift — two constants that must agree, drifted; one constant.
19. Per-tick log line starves the event loop — transition+heartbeat.
20. Defensive assert on a transient race aborts — retry, don't abort.
21. UI reflects local input, not the wire — read the publisher snapshot.
22. "Works on my machine" — Python dep drift; `uv add`, commit the lock.
23. The recovery path you trust is dead code — prove the trigger fires.
24. Raw infra detail or PII on an always-visible surface — mask by default.
25. Write "succeeds" into a path the reader never reads — share one resolver.
26. Layout overlap that keeps coming back — you fixed the cache, not the code.
27. Consumer builds against the maintainer's source tree — pin a published version.
28. Silently dropped function in a migration — surface-diff vs pre-migration source.
29. Still broken on a rig that never got the new build — diff the build stamps.
30. Behaviour selected by an env var, drifting across rigs — derive in code or a checked-in config.
31. Lost track of which services run — one declarative table + running-vs-declared diff.
32. "The link is up" but no data flowing — check the data layer too.
33. Aggregate health metric hides a single dead element — track liveness per element.
34. A check that's always red, so everyone ignores it — green-in-good-state or delete it.
35. Translated text shows boxes / all text thin & gray — font coverage + static instance.
36. Wrong-platform shared lib linked — select per platform+arch, verify the linked arch.
37. Authless "LAN-only" service the edge can reach — bind the LAN IP, reject at the edge.
38. GPU hang looks like "pipeline dead" — alive but fence-blocked; check `wchan`.
39. Build-time backend env bakes the wrong artifact — declared build var, stamped output.
40. "GPU" work silently on CPU / "loaded" hides 0 Hz — select explicitly, verify on output rate.
41. Compatibility gated on a version string — negotiate by feature set.
42. CPU↔GPU oscillation — measure with attribution, record the verdict, runtime switch.
43. Build-tagged device ≠ runtime device — one resolver for both, loud refusal on mismatch.
44. Widened a load-bearing cap to "use idle cores" — starved the peer it protected.
45. Dead after a clean-exit boot race / restart-looped a power-cycle fault — `Restart=always`, escalate.
46. "Hard floor" that was the wrong tool — a floor names its mechanism + alternatives ruled out.
47. Rebooted to make it go away — evidence lost, bug returns; capture first, escalate narrowest-first.
48. Consumer alive but publishes 0 — correlated streams on different clocks; fix the timestamp contract.
49. Subsystem fault blamed on the subsystem — real cause was starvation elsewhere; attribute first.
50. Frozen app missing a subsystem — native dep absent at bundle time; verify by importing entry points.
51. Closing the client stopped the always-on service — teardown detaches, never stops.
52. Buffered playback on a control feed — operator behind reality; single-slot latest-wins.
53. Works from source, fails on the compiled rig — no `-m`/source paths there; verify on the built form.
54. Runaway duplication from a non-idempotent external write — upsert by a stable id.
55. Stale because the system trusted event delivery — a reconcile poll is the correctness floor.
56. Web app 404s behind the reverse-proxy subpath — it assumed it owns `/`; relative URLs.
57. Parallel transfers 502 on a contended uplink while a tiny probe stays green — serialize; representative payloads.
58. Corrupt safety input passed a single-threshold gate — gate on correlated symptoms; verify applied.
59. Shipped the wrong codebase — `add -A` swept WIP, or a release built from a dirty tree.
60. The client set its own price/role — recompute server-side; the UI is not a security boundary.
61. Public demo wired to the production backend — isolate by construction, not by flag.
62. Whole stack frozen — one client leaked a capped shared resource via unbounded reconnect.
63. Topic alive at the producer, silent to new subscribers — logind reaped the user's IPC; diagnose by inode.
64. Consumer drops most of a fast stream — one read per tick; drain all per wake.
65. Adaptive lever re-initialized shared hardware live — wedged it under load; keep re-init out of live loops.
66. Calibration applied at the wrong resolution — geometry silently skewed; pin or scale, store the res.
67. Build "fixed" by poking flags — green but unreproducible; reproduce from a clean committed tree.
68. Peer "offline" — the shared edge throttled a one-shot new connection; keep-alive + backoff.
69. A second copy of critical-path logic drifted from the validated one — factor to one shared module.
70. A ported stack carried the upstream's hardware constants — re-derive from the actual unit.
71. Whole-stack crash-loop from one stale import in a gated-OFF module — the manager imports everything at init.
72. A cleanup glob deleted co-located bystanders — delete an explicit allowlist, never a wildcard.
73. Consumer pinned to a dead session's pushed override — expire by freshness, not value.
74. Hard cap overran — its eviction trusted a flaky signal; enforce with a deterministic key.
75. Control pill showed "ENGAGED" while the car sat in STANDBY — verify-after-write, reflect the read-back.
76. Ping-swept the LAN for a rig — ask the registry's `lan_ip`+`last_seen` instead; a scan can't tell rig from squatter.
77. Wrapper exited 0 while the work failed — propagate the child's status; test the failure path.
78. A test never seen red — it proves nothing; write it first, watch it fail for the right reason.
79. The test asserted on its own mock — green while the real integration is broken; assert on behaviour.
80. A fixed bug "came back" after a rebuild — the hot-edit on the box was never captured to the repo.
81. Core daemon died on first publish once a gate opened — a not-inert base class was a second publisher; sample the dead process's topics to find the collider.
82. Rate meter screamed an impossible number after a stall — smoothed 1/Δt through a burst; count in a window.
83. The fix was "in" but lived on an unmerged branch — and the checkout was parked there, so tools read the branch's reality. Merge / park-with-recorded-blocker / delete promptly; checkout back to the default branch; `git branch --no-merged` per repo is the tracking command.
84. `--clean` didn't update a .so — the wipe and the build disagreed where state lives: wrong-arm cache path, version-keyed reinstall of a content-changed same-version wheel, or an `rsync --update` mtime gate. Derive wipe paths from the build system; force-reinstall path wheels; content-compare installs.
85. Access granted by a shared password / copied key — can't revoke one person, can't audit who, one leak rotates everyone. Authorize each requester's OWN public key on a least-privilege account (forwarding-only/read-only) behind an approval gate; a public key transmits no secret (§26.4).
86. A "service" that's really a cron/calendar one-shot — idle between fires, never boot-starts, never self-heals, and "idle" reads as dead. If it must be always-on, run it as a resident loop under start-on-load + restart-on-exit supervision (RunAtLoad/KeepAlive, Restart=always); verify it shows RUNNING and respawns after a kill (§6.7).
87. A bootstrap that writes the files but doesn't commit — the next tool reads the committed/pushed/registered state, not files-on-disk, so it can't see the work and the manual finish is forgotten. Make the tool finish the handoff (commit/push/register); the finishing commit is path-limited to the files it owns (never `add -A`, WIP untouched) and idempotent (§18.7).
88. "Already up to date — nothing to do," but the last push failed: the skip-check compared a LOCAL marker (committed pointer) to the target, not the PUBLISHED state, so a committed-but-unpushed delta is stranded across every re-run. Gate "done" on `local == remote` (committed AND pushed); re-push a stranded fan-out commit directly (§18.7).
89. A one-shot operator action strands a half-done state — re-clicking errors ("already exists") or double-applies, so recovery needs a CLI. Make the GUI flow idempotent (each step checks its read-back end-state, "already done" = no-op) and re-run the one-click recovery path (§8.29).
90. Hand-rolled a one-off viewer (matplotlib dump, bespoke 3D widget) to debug a sensor/perception pipeline — N disconnected tools, no shared timeline, no replay. Log to Rerun (`rerun-io/rerun`) and let its viewer render/scrub/replay every modality on one clock; Rerun is a live/replay VIEW, never a record — view the canonical unomsg `.log`, never persist a `.rrd` (§8.30, §16.9).
91. A dropped connection mid-push/deploy read as "failed" — but the write had landed (the retry says "everything up-to-date"), or the *verify* step is what dropped. A transport error is on the confirmation channel, not the op: re-verify the end-state with a cheap idempotent read (`fetch`+`local==remote`, a `GET`) before retrying; make the write idempotent so a redo converges (§23.5).
92. A "keepalive publisher" opened on an input topic silently assassinated the real producer — daemon dies `send failed (-1)` shortly after another process starts, start-order-dependent, looks like a flaky transport fault. On a claim-on-create transport, *constructing* a publisher claims the topic; never open one on a topic you only consume (subscribers attach-or-create) (§5.3).
93. A plan/selection recomputed every tick flaps between near-equal options — downstream chases a jittering reference (looks like a noisy sensor / flaky downstream). The oscillation is self-inflicted by re-deriving instead of holding: re-validate the current decision and keep it while valid, recompute only on a real trigger, switch only past a margin (hysteresis) (§3.6).
94. Per-consumer adaptive loops over one shared cap climb together and collapse (~minute flap) — each reads its own queue "clear" and probes into the SAME shared headroom, so they multiply demand past the cap. Run ONE controller on the total budget; each share = budget ÷ active consumers (adding one scales shares down); dead-band + asymmetric smoothing; one throttle writer (§3.4).
95. New code shipped but its dependency was hand-installed into a build-regenerated dir (venv site-packages) — the next build/onboard wiped the dep while the code outside survived → silent degrade to a fallback, no crash. Install deps through the build's manifest/lockfile, ship code+dep as one paired unit through the repaved path, verify by loading on the rebuilt form (§13.4).
96. A new subscriber wasn't in the bridge's hand-maintained forward list — the topic never crossed, the consumer showed no data (not an error), and it was blamed on the source (a dead daemon / broken sensor) though the source published fine. Derive the forwarded set by type/interface (isinstance the subscriber base), not a parallel name-list; check the bridge forwards it (#1) before blaming the producer (§5.4).
97. Builds clean on the dev host, breaks on the target — a target-specific bug the host build hid (cfg branch never compiled, arch struct/syscall layout, FD-vs-classic frame, libc feature). The host build is not representative: cross-build to every target early/continuously off a declared matrix (one toolchain-activation command), then run on the target (§11.3).
98. A control link dropped but the actuator kept obeying the last command — runaway (held throttle/steer), because the consumer actuates on the last value with no freshness check (a dead link looks like 'operator holding the stick'). Check command freshness each tick on an unmaskable signal (timestamp/heartbeat, not a connected flag); past a small bound bail to a validated safe state; centralize in a watchdog (§3.7).
99. A binary only runs with `LD_LIBRARY_PATH`/`DYLD_FALLBACK_LIBRARY_PATH` set — "image not found" in a service/cron/clean shell/the rig. It has no baked rpath, so it finds its `.so`/`.dylib` only when an env var (which lives outside the artifact) points at it. Link a relative rpath (`$ORIGIN/../lib` / `@loader_path/../lib`) so it's relocatable; patchelf is a fallback; verify from a clean shell (§11.4).
100. A control loop hunts (~constant-freq actuator pulse, plant barely responding; impossible estimator values) because it closes on a PROXY that decoupled from the real plant — motor rpm as a stand-in for ground speed, decoupled by drivetrain slip. Close on the true controlled variable (fused ground speed); if a proxy is unavoidable, cross-check it against an independent signal and fail safe (§3.5) when they diverge (§3.8).
101. Edited a cross-language shared lib's internal `crates/` workspace, but consumers depend on its published thin `client/` — the change never shipped (or a consumer launched outside its repo root dies `UnknownService` because config resolves via `./config/` CWD-relative). Ship the published client surface, classify the ABI impact (additive vs wire/header bump), verify by building a CONSUMER, register the config table at init not from CWD (§28.2).
102. A silent duplicate of a singleton process — both instances write the same shared state (a topic, a `/tmp` slot, a throttle), so a setting won't hold / a value flaps / a stale config keeps driving; the producer looks healthy and the consumer gets blamed. Guard single-instance at startup (lock/claim, take-over-and-reap), reap the predecessor, expire stale pushed values (§7.6); diagnose by counting the writers (§6.8).
103. Mixed versions of a built lib — source says one version, the bytes on disk are older (a partial rebuild: one triple fresh, others stale; same pin, different bytes per machine). Make the artifact self-report its version (symbol/string/sidecar + git_sha), verify the version LOADED/linked not the source, rebuild + publish every triple from one version atomically (§28.3).
104. A clean rewrite drifted back into the legacy it replaces — legacy names/layout/identity crept in (types named after the old classes, a tree mirroring the legacy, the upstream's name in symbols/logs, an import of the old stack "just for now") until the new system is the old one in a new coat. New namespace+conventions all the way through (not just user-visible strings); depend on the legacy only at one narrow seam (schema as DATA, not code, §28.2); re-state defaults (§2.3); record the clean-break decision (§18.3) so drift is a flagged regression (§1 clean rewrite).
105. Two versions of the same shared lib in one dependency graph — a type mismatch where both types are the SAME name (`expected unomsg::Service, found unomsg::Service`), or a dylib with duplicate symbols. Same-named types from different lib versions are distinct and don't unify; two C-ABI copies are UB. Pin the shared lib once (one workspace dep), align every consumer to one version (fleet alignment); find the stray with the version stamp (§28.4).
106. Every log line carries its source twice — the logging framework's formatter already stamps ts + level + **target** (the component/module name) and the code *also* hand-prepends a `[component]` tag, so the identity doubles on every line (`[… INFO selfdrived] [selfdrived] …`); siblings also diverge (a bare `init()` next to a custom `Builder`, a library installing its own formatter, a supervisor re-logging a child's already-formatted stdout). Pick ONE owner of the prefix, one shared init/format across binaries, forward child output verbatim (§16.8).
107. A status/health badge reads "down/unreachable" while the system's real telemetry streams on screen (and flickers poll-to-poll) — it asks a SEPARATE out-of-band probe (a fresh SSH/HTTP handshake per poll) whose idle connection the edge drops/throttles (§23.3), not the live data link. Producer publishes its state as telemetry on the primary link; consumer derives up/down from telemetry liveness (data flowing ⇒ up); a probe only enriches detail, never overrides a live link; hold the verdict with hysteresis §3.6 (§15.10).
108. Two implementations of one host-singleton role run at once — a rewrite was deployed beside the legacy it replaces, both own the same device/topic/actuation authority → the stale/flap signature (#102), symptom on the VICTIM (no device / 0 Hz / load pegged), safety hazard if both actuate. The singleton guard was keyed on the BINARY, not the ROLE, so a `flock` on the new daemon's name never sees the legacy owner. Guard on the shared RESOURCE (device handle / topic claim §5.3 / actuation lock) so a foreign owner trips it; at onboard claim by DISABLING (not just stopping — "stopped" ≠ "gone", a still-enabled competitor re-grabs on next boot) every other implementation in both scopes (system + per-user), reaping orphans by exe-path not just the unit, disabling the whole registry-derived set (§5.4), at two enforcement points (privileged cutover for reboot-persistence + per-activation runtime claim). Disjoint resources may coexist; shared ones collide (§6.8).
109. The rewrite "runs" and passes unit tests but emits DIFFERENT numbers than the legacy (a wrong constant / dropped term / rounding / endianness / off-by-one) — checked for coverage (#28) and "it runs", never for behavioural PARITY. Downstream sees a subtle controls/perception bug nobody traces to the port. Dual-run legacy + rewrite on the SAME real recorded data (§16.9), assert equal (bit-identical or stated tolerance); cutover gate + CI regression guard; until it passes, UNVALIDATED → gated-inert (§20.1); a mismatch indicts the rewrite (§18.8).
110. A version-gated deploy ("skip cross-build if the rig already runs this revision") silently never ships the edit you're testing — the skip-check gated on the BARE commit sha, or computed "dirty" with `git diff` (unstaged-tracked only), so a STAGED or UNTRACKED edit carries the last commit's identity → "already current, skipping". Gate on `sha + dirty` with dirty = `git status --porcelain` (staged + unstaged + untracked); a `-dirty` stamp never matches (always rebuild); confirm "already current" against the version the TARGET reports (§28.3), not a local assumption (§12.3).
111. One torn record at the END of a log discards the WHOLE log — a writer killed mid-append (power cut / OOM / SIGKILL / full disk) leaves a torn trailing record (length prefix flushed, body cut short); a blind `read_exact(len)` hits EOF and errors the whole stream, throwing away every complete record before it (replay/upload "fails entirely", 99% intact). Treat a mid-record EOF at the end as a clean stop (`Ok(None)`) recovering all complete records (hard-error only on a torn record with valid records AFTER it); make completeness checkable (length prefix / per-record checksum); test against a truncated stream (§16.10).
112. Service stays DOWN after a restart, log says "another instance is already running" but `pgrep` shows none and the port/lock is free moments later — the supervisor reaped the old instance and restarted ~1s later, but the OS hadn't released the singleton's bound port (TIME_WAIT) / flock / pidfile yet, so the new instance's ONE-SHOT claim hit EADDRINUSE and exited (false "already running"). Restart outran teardown. Retry the claim over a bounded window (a few seconds); a genuinely-live peer never releases → still fail after the window (invariant holds); `SO_REUSEADDR` softens TIME_WAIT but the bounded retry is the general fix (§6.8).
113. The shipped bundle baked in the builder's personal config — token and all. A distributable/extractable artifact (installer, app, image, wheel) is a copy machine; snapshotting `~/.config` embeds the builder's shared bearer token, so it leaks to every recipient and any leak rotates the whole fleet. Ship a checked-in secret-free DEFAULT (URLs, non-secret targets, toggles); seed the credential per-device at runtime (operator's own key / provisioning / tokenless audited enrollment §26.4); gate the bake on a grep that refuses to package any token field (§14.5).
114. Fleet access by a key on every host — adding/revoking an operator means editing every host. Per-identity keys are right (§26.4) but a key on each host's `authorized_keys` is O(identities × hosts): it drifts (hosts missed), and revocation is per-host so stale access lingers. Stand up an SSH user CA; hosts trust the CA (`TrustedUserCAKeys`), an enrolled identity gets a short-lived signed cert and reaches every host (enroll once), a KRL revokes one identity fleet-wide instantly; guard the CA key as a fleet-wide secret + harden the front door (§26.5).
115. The version tag points at the wrong bytes — consumers pinned to vX.Y.Z either don't pick up the fix ("unusable"/nothing changed) or build stale content, and re-pushing the tag doesn't help. The tag was MOVED (re-pointed, but resolvers cache tag→sha so it doesn't propagate; `git push` refuses without `--force`) or POISONED (a broken/partial publish tagged the wrong commit / tag landed but content didn't, #91). A version tag is a contract (number → exact bytes). Treat tags as immutable; BURN the bad number and cut a fresh higher one (poisoned v0.1.12 → re-cut v0.1.13, never re-push v0.1.12); verify from a CLEAN fetch (right stamp §28.3 + content) before announcing (§28.5).
116. The teardown path crashes the worker it was supposed to stop — a decoder/subprocess/thread segfaults or corrupts state ON EXIT (works in steady state). The stop sent SIGTERM/SIGKILL (or dropped the handle) IMMEDIATELY, mid-operation, while the worker held a codec context / dlopen'd state / lock / in-flight DMA — the forced kill raced the op. Teardown is two phases: cooperative stop first (set a stop_event the loop checks, wait bounded for a safe exit that releases the resource), forceful escalation only on a hang. An immediate kill makes the teardown path itself the bug (§6.9).
117. A benign non-zero aborts the whole build / onboard — an empty glob (`ls -t build/*.whl` on a clean tree), a `grep` with no hits, or an `install some_optional.py` for a file an older checkout lacks ("cannot stat") dies under `set -e`/`pipefail`, even though the real work would succeed. The non-zero step was AUXILIARY, not the work; "nothing to do" was misread as failure. Guard the genuinely-optional / may-be-empty step (`|| true`, `[ -f ]`, consume-when-present) so it degrades + logs; ship a script + the files it references as one bundle (optional sibling in an optional file-set, read with `if [ -f ]`); NEVER blanket `|| true` the essential work (that's the §18.4 false-green). Discriminator: is this step the work, or auxiliary to it? (§18.4).
118. Untrusted content became code — a stored job/booking name like `<script>…</script>` runs in every viewer's session (XSS), an input `'; DROP TABLE …` runs in the DB (SQLi), a filename `; rm -rf` runs in a shell. Untrusted data was interpolated RAW into a string an interpreter parses; it can't tell your structure from the payload. Output: render via an auto-escaping engine, encode for the exact context (HTML body vs attr vs JS vs URL). Input: parameterize, never interpolate — bound query params, an argv array (never `shell=True`/concatenated SQL). Encode at the SINK on the server; treat stored values as untrusted when rendered (stored XSS). Client-side escaping is cosmetic (§26.6).
119. The sensor reads "invalid" but the hardware is fine (opening the device by hand works) — the daemon, running under systemd as a user, lacks the OS group to open its device node (a serial TTY is `root:dialout` 660). You're in `dialout` INTERACTIVELY; the SERVICE isn't — its groups are the unit's (`User=`/`SupplementaryGroups=`), not your shell's. The open got `PermissionError [Errno 13]`; the daemon swallowed it (slept) or crashed once and wasn't restarted → "no data" downstream → you debug the hardware. Grant the access in the version-controlled UNIT (`SupplementaryGroups=dialout`/capability/udev ACL); make a device-open failure loud (retry+WARNING §18.9 / operator indicator §3.5), never silent-sleep or one-shot-crash-stranded (`Restart=always` §6.2); the OS error may be WRAPPED (pyserial→`SerialException`) — match the errno (§6.10).
120. `Restart=always` but the service is permanently DOWN — a consumer shows frozen/stale data ("carState delayed", "no updates") and a hand-restart fixes it. The unit flapped fast enough (a dependency-flap window, repeated relaunches, a crash-loop) to hit systemd's start-limit (default 5 starts/10s) → systemd GAVE UP and left it `failed` indefinitely; `Restart=always` is overridden. Often triggered by a too-aggressive `TimeoutStopSec` (a slow stop → `SIGKILL`/`failed(timeout)` burns the budget). Set `StartLimitIntervalSec=0` in `[Unit]` (no-op'd in `[Service]`) + a generous `TimeoutStopSec`; first diagnostic for "stale data" from a supervised service = `systemctl is-active <unit>` (stale `/dev/shm` + a rate probe read the dead producer's last values, §15.10) (§6.2).
121. A real fault shows as benign — an operator misses a down link / dropped control authority because its indicator is the same neutral gray as a feature that's simply off (or a normally-absent signal glows red and gets ignored). The boolean→colour helper used a FIXED "off" colour, but off/false/absent is PER-SITE semantic: normal at one indicator (gray), a fault at another (red), noteworthy at a third (amber). The status→colour helper takes the off-meaning per call site (`off=IDLE|WARN|BAD`); colours still come from the one palette (§8.25), only the off-semantic is per-site; carry state in shape too (filled vs hollow dot) (§8.25).
122. The submodule broke the build — `fatal: transport 'file' not allowed`, or empty dirs where a shared submodule (rules/config/proto) should be, or CI can't reach the URL. A submodule was used for content that must merely BE PRESENT, so it carries a fetch/init/transport step that fails independently of the content: git 2.38+ blocks the `file://` transport for submodules + `url.insteadOf` local-mirror rewrites (CVE-2022-39253); a clone without `--recurse-submodules` leaves empty dirs; a private URL fails in CI. Vendor committed COPIES + a path-limited copy-in-and-commit step (fresh clone = zero setup); reserve submodules/prefix-deps for versioned code with its own lifecycle (§13.2), and even then the URL must be reachable from every consumer, never `file://` (§13.5).
123. A gray/smeared camera tile at the CORRECT size (or a sibling stuck "waiting for stream") = encoder-side starvation on a thin uplink, NOT a GUI/decode/stride/resolution-mismatch bug. The geometry being right is the tell it isn't the renderer (a display reshaping on the writer's own w,h can't emit a correctly-sized wrong picture; SPS carries the true size inline every IDR). Gray-but-sized = bitrate floor (ABR ~77 kbps → DC-only macroblocks = flat-gray; "streaks" = surviving low-freq luma) — shrink encode res by a link-profile PRESET via camerad restart (never a live re-cap, #65). Stuck "waiting for stream" = IDR starvation (force-IDR wired to the wrong platform API → no keyframe to re-seed). Rule out the GUI by construction (reshape on writer's w,h, 32-aligned), then decode the EncodeData bytes at the source with plain ffmpeg (§3.4).
124. Bulk upload between two co-located hosts 502'd — "pull latest" arms but nothing lands; uploader logs upload_start→502 on every multi-MB file while a 16-byte probe returns 201. The transfer detoured rig→thin metered WAN up (~90 KB/s)→cloud edge→tunnel back down→Server even though rig and Server share a LAN; a 6 MB PUT took ~70s (at the read timeout) and 502'd when teleop competed → the force-upload flag never cleared → backlog never drained. Big-file-only failure on a thin uplink = bandwidth starvation, not a dead endpoint (§9.9). Route bulk data LAN-direct when the peer's registry lan_ip is on your LAN (§23.4), relay through the WAN only off-LAN, derive the target from the registry not an env var (§7.5), and size the timeout to bytes÷worst-case-bandwidth.
127. A code fix "didnt take" no matter how many edits — the RUNNING process was a COMPILED copy, not the source you touched. Edits deploy/restart with no effect, your new log line never prints. Not a stale cache — the runtime loads a DIFFERENT artifact than the source you edit: a Cython/.so, frozen binary, .pyc, installed wheel in site-packages, or container layer, while you edit the source tree next to it (seen: rig ran modeld.*.so from site-packages, edits went to ~/unofsd-build/…/modeld.py; a gdb py-bt showing modeld.c revealed it after 3 "failed" fixes that never ran). Before iterating, PROVE which artifact runs: readlink /proc/<pid>/exe, python -c "import m;print(m.__file__)" in the RUNTIME env, gdb -p <pid> py-bt, lsof. Edit the source of record + rebuild/redeploy — never hot-patch the copy that isnt loaded; mark any build-cache tree so the wrong copy cant be mistaken for runtime (§18.5.1, §18.9).
126. A fixed bug came back after an UNRELATED change (or a mechanical cleanup — `ruff --fix`, remove-unused, a formatter) — whack-a-mole: fix B, bug A returns. Not a hard bug — an UNGUARDED one: the original fix left no executable guard, so nothing red-flagged its reversal. Either deliberate-looking-wrong code (a re-export nothing local uses, a specific list ORDER, a magic const) got "cleaned up", or two fixes are a constraint-pair and the new one silently violated the old un-encoded one. Ship a permanent regression guard with EVERY fix (§18.5.1); when a later change reds an old guard, reconcile both — never delete/xfail it; mark deliberate-looking-wrong code in place with reason + guard pointer (§18.5.1).
125. A renamed heartbeat field greyed out every consumer still reading the old name — a per-host button (upload / pull-latest) disabled or "no net" for a plainly-connected host, only some UIs affected. The producer renamed a schemaless telemetry key (network_type→info.uplink_kind) and swept only one repo's consumer; every other does info.get("network_type")→"" — no crash, just a falsy read that fails the gate. An untyped dict has no compiler to catch the drift (§18.2 migration-incompleteness across repo consumers). Sweep EVERY consumer fleet-wide, read with an old-name fallback (uplink_kind or network_type or ""), treat the payload as append-only (§4).
